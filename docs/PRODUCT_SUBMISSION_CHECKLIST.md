## B. Ownership and authority

- [ ] Owner/operator identity and authority to publish are evidenced.
- [ ] Agency authority to distribute, host, market or resell this exact product is recorded.
- [ ] Third-party, client, employer, contributor and open-source obligations are checked.
- [ ] Product name, trademarks, logos and branding permissions are documented.
- Evidence reference / reviewer / date:

## C. Product facts and visuals

- [ ] Feature claims are checked against the reviewed commit or tested live behavior.
- [ ] Limitations, dependencies and unsupported use cases are disclosed.
- [ ] Demo is tested at the exact URL and date recorded.
- [ ] Screenshots are authentic or visibly labelled illustrative.
- [ ] Exact assets, rights holders, allowed channels/edits and sensitive-data inspection are recorded.
- [ ] Owner approves the exact public copy and assets.
- Evidence reference / reviewer / date:

## D. Licensing and third-party notices

- [ ] Exact licence file and version are reviewed.
- [ ] Copyright notices and attribution obligations are preserved.
- [ ] Dependencies, fonts, icons, templates, datasets, bundled media and SDK terms are reviewed.
- [ ] Model/provider/service terms are reviewed where applicable.
- [ ] Proposed hosted, source redistribution and binary distribution models are covered.
- [ ] Legal reviewer/owner decision and evidence are recorded.
- Evidence reference / reviewer / date:

## E. Technical release artifact

- [ ] Version and release commit are frozen.
- [ ] Build instructions and reproducible inputs are recorded.
- [ ] Distribution artifact exists and its SHA-256 (or equivalent) is recorded.
- [ ] Supported OS/browser/runtime, resources and network needs are documented.
- [ ] Environment configuration is documented without exposing secret values.
- [ ] Clean-environment install/deploy test passes and logs are retained.
- [ ] Upgrade, migration, backup/restore and rollback procedures are tested where relevant.
- [ ] Known issues and compatibility constraints are published.
- Evidence reference / reviewer / date:

## F. Security, privacy and data handling

- [ ] Data categories, purpose, storage location, retention and deletion are documented.
- [ ] External providers/subprocessors and data transfers are identified.
- [ ] Authentication, authorization and tenant isolation are tested where relevant.
- [ ] Secrets remain server-side and credential rotation/revocation is defined.
- [ ] Logging, backups, vulnerability handling and incident response are reviewed.
- [ ] AI/model products disclose provider use, limitations, cost/rate controls and input handling.
- Evidence reference / reviewer / date:

## G. Commercial terms (only for a proposed paid offer)

- [ ] Authority to sell/license is approved.
- [ ] Price, currency, billing cadence and inclusions are approved.
- [ ] Tax/invoice and supported-region requirements are reviewed.
- [ ] Refund, cancellation, renewal, transfer, seat and installation limits are approved.
- [ ] Fulfilment and customer access model is tested.
- [ ] Support scope, response expectations, maintenance and end-of-life terms are approved.
- [ ] No payment or purchase CTA appears before the commercial gate passes.
- Evidence reference / reviewer / date:

## H. Support, updates and retirement

- [ ] Named support owner and contact route.
- [ ] Coverage hours and response targets (only if approved).
- [ ] Supported versions and compatibility window.
- [ ] Security patch and update policy.
- [ ] Change-history publication owner.
- [ ] Data export, migration, withdrawal and end-of-life plan.
- Evidence reference / reviewer / date:
